# 리뷰 읽기 — 상태 대장

> **이 파일은 `.tsv` 였다.** 첫 커밋 시도에서 `.gitignore` 가 막았다 —
> PUB-7 이 *"이 저장소는 어떤 데이터 파일도 추적하지 않는다"* 이고, `no-learner-data.yml`
> 이 반대편에서 같은 규칙을 강제한다. **강제로 추가했다면 오늘 두 번째 게이트를 빨갛게
> 만들었을 것이다.** 확장자만 바꾸면 정책을 우회하는 것이므로, **문서로 만들고 데이터 행을
> 코드펜스 안에 둔다.** 탭 구분은 그대로라 파서는 바뀌지 않는다.

```
# .study/리뷰 읽기 — 상태 대장 (single source of truth)
#
# WHY THIS FILE EXISTS.
# 이 트랙은 2026-08-10부터 08-21까지 여섯 번, 자기 문서 안에서 거짓이 된 문장을 만들었다.
# 0장 §상태  "1장 착수"            — 1장이 4장으로 강등된 뒤 이레 동안        (사람이 전문을 읽다 발견)
# 7장 §다음 장 "없습니다"           — 8·9장이 도착한 뒤                        (PO가 물어서 발견)
# 2장 §다음 장 "3장 미착수"          — 3장을 쓰는 중에                          (스스로 발견)
# 1장 §닫는 말 "0장을 아직 안 고쳤다" — 같은 커밋에서 고쳤으므로                  (스스로 발견)
# 4장 §4.7  "#12880 열려 있음"      — 2026-08-05 이후 병합됨, 16일간 거짓        (대장이 발견 ← 이 파일)
# 0장 §0.3  "이 방법의 전제"         — 표본 하나로 일반화                        (2·3장이 발견)
# 여섯 중 다섯을 사람이 잡았다. 저장소가 잡은 것은 없다.
#
# 원인은 "검사가 없다"가 아니다. docs-consistency.yml 이 있고 CHECK 1 은 이 폴더도 본다.
# 원인은 이 폴더의 상태 주장이 **산문으로, 여러 문서에 복제되어** 적혀 있었다는 것이다.
# 복제본은 원본이 움직여도 따라오지 않는다.
#
# WHAT THIS FILE IS.
# 이 폴더가 하는 모든 **상태 주장**의 유일한 출처. 장이 존재하는가, 어떤 PR 이 열려 있는가.
# 검사.sh 가 이 파일을 파일시스템·GitHub API 와 대조한다. 산문은 이 파일을 가리키고,
# 상태를 다시 적지 않는다.
#
# WHAT THIS FILE CANNOT DO.
# 문장이 참인지는 못 본다. **문장이 무엇을 주장하는지도 못 본다.** 여기 있는 것은
# 기계가 대조할 수 있는 것뿐이고, 그건 이 폴더가 만든 거짓 여섯 개 중 둘(장 존재, PR 상태)이다.
# 나머지 넷은 여전히 사람이 전문을 읽어야 잡힌다. **줄인 것이지 없앤 것이 아니다.**
#
# 그리고 이 목록이 **완전한지도 기계가 못 본다.** 장에 적힌 `#12345` 를 전부 요구하는
# 검사를 생각했다가 버렸다 — 밀도표에 나오는 PR 번호는 **그때 측정한 기록**이지 상태
# 주장이 아니고, 둘을 가르려면 산문을 읽어야 한다. 실제로 4장의 #3695 는 2026-08-21
# 현재 이 대장에 없다(레이트리밋으로 실측 못 함). **앵커를 빠뜨리는 것은 검사가 못 잡는다.**
# (docs-consistency.yml 이 산문 검사를 하나 썼다가 버린 이유가 여기 그대로 적용된다 —
# 이 폴더는 거짓이 된 문장을 ⚠ 로 인용해서 보존하므로, 키워드 검사는 정정문에도 반드시 걸린다.)
#
# 열: kind  repo  id  state  measured  chapter  note
# chapter: id=장 번호, state=written|planned, chapter 열=파일명
# anchor : id=PR 번호, state=open|merged|closed, chapter 열=인용하는 장 번호
# state 는 measured 날짜에 실제로 조회한 값이다. 추정치를 쓰지 않는다.
#
#
#
```
